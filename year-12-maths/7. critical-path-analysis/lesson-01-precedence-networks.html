Theory

Project networks

Critical path analysis is a method for scheduling projects. It answers two questions: how quickly can this project finish? and which tasks must not be delayed?

Activity-on-edge convention

In this course, activities are the edges (arrows) and vertices are events — moments in time when activities finish and others may begin. Each edge is labelled with the activity's letter and its duration.

Activity A takes 5 units and must finish before B (3 units) can start. The whole project takes 8 units.

The rules

  • An activity can only start once every activity arriving at its starting vertex has finished.
  • The network has one start vertex (nothing arrives) and one finish vertex (nothing leaves).
  • Arrows point in the direction of time — the network never loops back.

Method

Reading a precedence table

A precedence table (also called an activity table) lists each activity, how long it takes, and which activities must be completed immediately before it.

Worked example 1

ActivityDuration (days)Immediate predecessors
A4—
B6—
C3A
D5A, B
E2C, D

How to read it:

  • A and B have no predecessors, so both start immediately.
  • C waits for A alone.
  • D waits for both A and B — it cannot start until the later of the two finishes.
  • E waits for both C and D, and is the final activity.

"Immediate" predecessors

Only the activities directly before are listed. In the table above, E also depends on A (through C), but A is not listed for E because the dependency is indirect. Never draw an arrow for an indirect dependency.

  2. F depends on E, and E depends on C and D. What are F's immediate predecessors?
    Show working

    Only E. C and D are indirect predecessors of F, so they are not listed.

Method

Drawing the network

The procedure

  1. Draw the start vertex and every activity with no predecessors leaving it.
  2. Work down the table. Each activity starts at the vertex where all its predecessors end.
  3. Join every activity with no successors to a single finish vertex.
  4. Number the vertices so every arrow points from a lower to a higher number.

The network for Worked example 1. The dashed arrow is a dummy activity, carrying A's completion across to where D starts.

Worked example 2 — why the dummy is needed here

C depends on A only. D depends on A and B.

If A and B both ended at the same vertex, then C would appear to depend on B as well — which is wrong. If they ended at different vertices, D could not see both.

The solution: A ends at vertex 2 and B ends at vertex 3. A dummy activity of zero duration runs from vertex 2 to vertex 3, carrying the information that A has finished. Now C leaves vertex 2 (depending on A alone), while D leaves vertex 3 (depending on B and, via the dummy, on A).

Your turn

  1. A project has A (2, —), B (4, A), C (3, A), D (5, B, C). A student draws B and C both from vertex 2 to vertex 3. What is wrong, and how is it fixed?
    Show working

    Two activities would join the same pair of vertices, so they cannot be told apart. Let C end at a new vertex 4 and add a dummy from 4 to 3. D leaves vertex 3, so it still waits for both B and C.

  2. How many vertices does the corrected network have, and what is the project's length?
    Show working

    Five vertices: start, end of A, the merge vertex, the extra vertex for C, and the finish. Length: \(2 + \max(4, 3) + 5 = 11\).

Theory

Dummy activities

What a dummy is

A dummy activity is a dashed arrow of zero duration. It consumes no time and no resources. Its only job is to show a dependency that cannot otherwise be drawn correctly.

The two reasons for a dummy

  1. Overlapping dependencies. Two activities share some but not all predecessors — as with C and D above.
  2. Uniqueness. Two activities would otherwise run between the same pair of vertices, making them impossible to tell apart.

Worked example 3 — the uniqueness case

Activities P and Q both start after R and both finish before S. Drawn naively, P and Q would run between the same two vertices.

Fix: let P run from vertex 2 to vertex 3, and Q from vertex 2 to a new vertex 4. A dummy then runs from vertex 4 to vertex 3. P and Q now have distinct endpoints, and S still waits for both.

Rules for dummies

  • Always drawn dashed, always duration 0.
  • Still has a direction — dependencies flow one way only.
  • A dummy can lie on the critical path, contributing zero time.
  • Use the fewest dummies that correctly capture the dependencies.

Is a dummy needed?

Type yes or no.

Your turn

  1. G depends on E; H depends on E and F. Is a dummy needed? Where would it go?
    Show working

    Yes — G and H share some but not all predecessors. E and F end at different vertices; G leaves E's vertex; a dummy runs from E's vertex to F's vertex, and H leaves F's vertex.

  2. P (3 days) and Q (5 days) both depend on M, and N depends on both P and Q. Why is a dummy needed?
    Show working

    Uniqueness: P and Q would both run from M's end vertex to N's start vertex. End one of them at a new vertex and join it to N's start with a dummy.

(a) Explain why a dummy is needed. [1 mark]

H depends on E alone, but F depends on E and D. They share some predecessors, so E ends at its own vertex (where H starts) and a dummy carries E's completion to the vertex where D ends and F starts.

(b) List every path and find the minimum completion time. [2 marks]

PathLength
A–E–dummy–F–G\(3 + 2 + 0 + 3 + 2 = 10\)

Application

From a description to a network

The syllabus says networks are built from "a precedence table or equivalent". Often the equivalent is a written description. Turn it into a table first, then draw.

  1. List every task, give it a letter, and note its duration.
  2. For each task ask: what must be finished immediately before this can start? Record only the direct predecessors.
  3. Check: at least one task has no predecessors, and at least one is not a predecessor of anything.
  4. Draw the network from the table.

Worked example 6

"To run a fundraiser barbecue, we first book the venue (2 days). Once it is booked we can order the food (3 days) and print flyers (1 day). Flyers are distributed (2 days) after printing. Set-up (1 day) happens once the food has arrived and the flyers are out."

ActivityTaskDaysPredecessors
ABook venue2—
BOrder food3A
CPrint flyers1A
DDistribute flyers2C
ESet up1B, D

The network splits after A, then merges before E. Both paths, A–B–E and A–C–D–E, take 6 days, so the barbecue can be ready in 6 days.

Class activity

Make each path the longest

About 10 minutes · pairs. Use the network builder. It has three paths: A–C–E, B–D–E and A–dummy–D–E.

  1. With the starting durations (A 4, B 6, C 3, D 5, E 2), record each path's length. Which is longest?
  2. Change only A so that the path through the dummy is the longest. What is the smallest value of A that does it?
  3. Reset. Find durations that make A–C–E the longest path. Write the condition, in terms of the durations, for this to happen.
  4. Find a set of durations where all three paths are equally long. What would that mean for a project manager?
  5. E is on every path. Explain why changing E never changes which path is longest.
Discussion points

1. A–C–E 9, B–D–E 13, A–dummy–D–E 11. B–D–E is longest.

2. A–dummy–D–E beats B–D–E when \(A > B = 6\), so the smallest whole value is A = 7, giving lengths 12, 13 and 14.

3. For example A 4, B 3, C 7, D 2: lengths 13, 7 and 8. The condition is \(C > D\) and \(A + C > B + D\).

4. For example A 6, B 6, C 5, D 5, E 2: all three are 13. Every activity is then critical — any delay anywhere delays the project.

5. Adding to E adds the same amount to every path, so their order never changes.
