Theory

Paths and Trees

Walk, Trail, Path, Circuit and Cycle

A route through a network can be classified more precisely depending on whether it repeats vertices or edges, and whether it starts and ends at the same vertex:

  • Walk — any route along edges from one vertex to another; vertices and edges may be repeated freely.
  • Trail — a walk that does not repeat any edge (vertices may still repeat).
  • Path — a trail that also does not repeat any vertex. Every path is a trail, and every trail is a walk, but not the other way around.
  • Circuit — a closed trail: it starts and ends at the same vertex, with no repeated edge (other vertices along the way may repeat).
  • Cycle — a closed path: it starts and ends at the same vertex, with no repeated edge and no repeated vertex other than that shared start/end.

Worked Example

Using the network below (edges A–B, B–C, C–D, D–A, A–C), classify the route A → B → C → A → D.

The edges used are A–B, B–C, C–A and A–D — no edge is repeated, so it's at least a trail. However, vertex A is visited twice, so it is not a path. It also doesn't finish where it started (it ends at D, not A), so it is not a circuit either. This route is a trail (and therefore also a walk), but not a path, circuit or cycle.

A tree is a connected network that contains no cycles — there is exactly one path between any two vertices in a tree. A network that contains a cycle (a route that starts and ends at the same vertex without repeating an edge or vertex) is not a tree.

Theory

Eulerian Trails and Circuits

An Eulerian trail is a trail that uses every edge of a network exactly once (vertices may be revisited). An Eulerian circuit is a closed Eulerian trail — it uses every edge exactly once and finishes back where it started.

Whether one exists can be tested just by looking at the degrees of the vertices:

  • An Eulerian circuit exists if and only if the network is connected and every vertex has even degree.
  • An Eulerian trail (that isn't necessarily closed) exists if and only if the network is connected and exactly 0 or 2 vertices have odd degree. If there are 2 odd vertices, every Eulerian trail must start at one and end at the other.
  • If more than 2 vertices have odd degree, no Eulerian trail (or circuit) exists at all.

The same network from earlier in this lesson (edges A–B, B–C, C–D, D–A, A–C)

Worked Example

Does this network have an Eulerian trail or circuit?

Degrees: \(\deg(A) = 3\) (edges to B, D, C), \(\deg(B) = 2\), \(\deg(C) = 3\) (edges to B, D, A), \(\deg(D) = 2\).

Exactly two vertices (A and C) have odd degree, so an Eulerian trail exists — it must start at A and end at C (or start at C and end at A), for example A→B→C→D→A→C. Since not every vertex has even degree, there is no Eulerian circuit.

History

The Königsberg Bridge Problem

The Eulerian trail test was first developed by Leonhard Euler in 1736 to settle a famous puzzle. The city of Königsberg was built around four landmasses — two river banks and two islands — joined by seven bridges. Could a resident walk through the city and cross every bridge exactly once?

A = North bank, B = South bank, C = Kneiphof island, D = East region — A–C and B–C each have 2 bridges

Worked Example

Model Königsberg as a network and decide whether the walk is possible.

Degrees: \(\deg(A) = 3\) (2 bridges to C, 1 to D), \(\deg(B) = 3\) (2 bridges to C, 1 to D), \(\deg(C) = 5\) (2 to A, 2 to B, 1 to D), \(\deg(D) = 3\) (1 each to A, B, C).

All four vertices have odd degree — far more than the 0 or 2 allowed for an Eulerian trail. Euler proved that no route exists that crosses every bridge exactly once, whatever the starting point.

Theory

Hamiltonian Paths and Cycles

A Hamiltonian path visits every vertex of a network exactly once (it doesn't need to use every edge). A Hamiltonian cycle is a closed Hamiltonian path — it visits every vertex exactly once and returns to its starting vertex.

This is a different focus from Euler's trails and circuits: Eulerian routes are about using every edge once, while Hamiltonian routes are about visiting every vertex once.

Worked Example

Does the network from the Eulerian Trails section (vertices A, B, C, D) have a Hamiltonian cycle?

Yes — the route A→B→C→D→A visits every vertex exactly once and returns to A, using edges A–B, B–C, C–D and D–A. This is the same cycle we identified earlier in "Paths and Trees"; it happens to also be a Hamiltonian cycle.

Unlike Euler's clean degree-based test, there is no simple general rule for deciding whether a Hamiltonian path or cycle exists — in general you have to search for one directly. For example, a network made of two triangles joined at a single shared vertex has no Hamiltonian cycle, because the shared vertex would need to be visited twice to travel from one triangle to the other.

Theory

Spanning Trees and Minimum Spanning Trees

A spanning tree of a network is a tree that includes every vertex of the original network, using only a subset of its edges (with no cycles). A network can have several different spanning trees.

A minimum spanning tree (MST) is the spanning tree whose edges have the smallest possible total weight. It is the cheapest way to keep every vertex connected.

Theory

Finding a Minimum Spanning Tree: Kruskal's Algorithm

One reliable method — called Kruskal's algorithm — is:

  1. List every edge in order from smallest to largest weight.
  2. Add edges one at a time, smallest first, skipping any edge that would create a cycle with edges already chosen.
  3. Stop once every vertex is connected (a network with \(n\) vertices needs exactly \(n-1\) edges in its spanning tree).

Consider this weighted network of four relay stations, A, B, C and D:

Bold edges show the minimum spanning tree; faint edges were not needed

Worked Example

Edges sorted by weight: A–C (1), B–D (1), A–B (2), B–C (2), C–D (2), A–D (5).

Add A–C (1) — no cycle. Add B–D (1) — no cycle (a separate pair). Add A–B (2) — connects the two pairs, no cycle. All 4 vertices are now connected with 3 edges, so the tree is complete.

B–C, C–D and A–D are skipped, since each would create a cycle. Minimum spanning tree weight \(= 1 + 1 + 2 = 4\).

Theory

Prim's Algorithm

Kruskal's algorithm builds the minimum spanning tree by picking cheap edges from anywhere in the network. Prim's algorithm takes a different approach — it grows a single tree outward from one starting vertex:

  1. Start with any one vertex as the (one-vertex) tree.
  2. Look at every edge connecting a vertex already in the tree to a vertex not yet in the tree, and add the cheapest one.
  3. Repeat until every vertex has been added.

Because every edge added always joins a new vertex to the growing tree, Prim's algorithm can never create a cycle — there's no need to check for one.

Worked Example

Apply Prim's algorithm to the M, N, O, P, Q network from Exercise 2, starting at M.

Tree = {M}. Cheapest edge out of M: M–N (3). Add N. Tree = {M, N}.

Cheapest edge out of {M, N}: N–O (4). Add O. Tree = {M, N, O}.

Cheapest edge out of {M, N, O}: O–P (2). Add P. Tree = {M, N, O, P}.

Cheapest edge out of {M, N, O, P}: P–Q (5), versus M–Q (8) — P–Q is cheaper. Add Q. All 5 stations are now connected.

Total weight \(= 3 + 4 + 2 + 5 = 14\) — exactly the same minimum spanning tree Kruskal's algorithm found, reached by a different process. Whichever correct method you use, the minimum total weight for a given network is always the same.

Theory

Solving Minimal Connector Problems

Minimum spanning trees solve connector problems — real-world situations where you need to connect every location in a network (with roads, cables, pipes, etc.) using the least possible total length or cost, without needing every possible direct connection. Either Kruskal's or Prim's algorithm can be used to solve them — both always find the same minimum total.

Worked Example

A telecommunications company wants to connect relay stations A, B, C and D from the diagram above using the least total cable length. What is the minimum length required, and which links should be built?

This is exactly the minimum spanning tree found above: build A–C, B–D and A–B, for a total cable length of \(4\) units. Building B–C, C–D or A–D as well would waste cable, since every station is already connected.

Connector problems are often given as a table rather than a diagram — the same algorithms apply either way.

Theory

Shortest Paths in Networks

The shortest path between two vertices is the route between them with the smallest total weight. For small networks (up to 10 vertices), the shortest path can be found by listing the possible routes and comparing their total weights.

Worked Example

Using the network of relay stations above, find the shortest path from A to D.

Route A–B–D: \(2 + 1 = 3\)

Route A–C–D: \(1 + 2 = 3\)

Route A–D direct: \(5\)

The shortest path has weight \(3\) — there are two equally short routes, A–B–D and A–C–D.

Theory

Dijkstra's Algorithm

Listing every possible route works for tiny networks, but becomes impractical as a network grows. Dijkstra's algorithm is a systematic method that finds the shortest distance from one starting vertex to every other vertex, one step at a time:

  1. Give the starting vertex a distance of \(0\), and every other vertex a tentative distance of \(\infty\) (unknown).
  2. Visit the unvisited vertex with the smallest tentative distance ("settle" it — its distance is now final).
  3. For each of its neighbours, check if the route through the settled vertex is shorter than their current tentative distance; if so, update it.
  4. Repeat steps 2–3 until every vertex has been settled.

Step 1: settle M (distance 0). Its neighbours N and Q get tentative distances \(0+3=3\) and \(0+8=8\).

Step 2: the smallest unsettled distance is N (3). Settle N. Its neighbours: O gets \(3+4=7\); P gets \(3+6=9\).

Step 3: the smallest remaining is Q (8), which is less than P's 9 — settle Q. Its only unsettled neighbour, P, would get \(8+5=13\) via Q, which is worse than P's existing 9, so no update.

Step 4: settle O (7). Its neighbour P would get \(7+2=9\) via O — the same as P's existing distance, so no change.

Step 5: only P remains — settle it (9). Every vertex is now settled.

Final shortest distances from M: \(N=3\), \(O=7\), \(Q=8\), \(P=9\). This matches the earlier result that the shortest path from M to Q has weight 8 — Dijkstra's algorithm just finds it (and every other distance from M) systematically, without having to list every possible route by hand.

Theory

Shortest Path vs Minimum Spanning Tree

A shortest path between two vertices is not necessarily the same as the route between them within a minimum spanning tree, and it isn't always the "best" choice if other factors matter too. The MST minimises the total weight connecting every vertex — it does not aim to minimise the distance between any one specific pair.

Solid bold = minimum spanning tree; dashed = the direct shortest path C–D (not part of the MST)

Worked Example

Using the same network, compare the shortest path from C to D with the route between C and D inside the minimum spanning tree.

Direct edge C–D: weight \(2\).

Route within the MST, C–A–B–D: \(1 + 2 + 1 = 4\).

The shortest path from C to D is the direct edge (weight 2) — but that edge was not included in the minimum spanning tree, since it would have created a cycle. This shows that a shortest path is not necessarily contained in any minimum spanning tree.

Worked Example

The same idea applies to the M, N, O, P, Q network from Exercise 2. Compare the shortest path from M to Q with the route between them inside the minimum spanning tree.

Direct edge M–Q: weight \(8\).

Route within the MST, M–N–O–P–Q: \(3 + 4 + 2 + 5 = 14\).

Once again, the shortest path (the direct edge, weight 8) is not part of the minimum spanning tree — it was excluded because it would have created a cycle, even though it's the fastest route between just these two stations.

Practice: Putting It All Together

Here is a new weighted network of six vertices, R, S, T, U, V and W.

R–S (4), S–T (3), T–U (2), U–V (5), V–W (4), W–R (6), R–V (9), S–U (7)

Worked Example

Find the minimum spanning tree of this network.

Sorted edges: T–U (2), S–T (3), R–S (4), V–W (4), U–V (5), W–R (6), S–U (7), R–V (9).

Add T–U, S–T, R–S, V–W (no cycles so far — two separate groups: {R,S,T,U} and {V,W}). Add U–V — this connects the two groups. All 6 vertices are now connected with 5 edges, so the tree is complete.

Minimum spanning tree weight \(= 2 + 3 + 4 + 4 + 5 = 18\).

Worked Example

Find the shortest path from R to U.

Route R–S–T–U: \(4 + 3 + 2 = 9\)

Route R–V–U (using the diagonal): \(9 + 5 = 14\)

The shortest path from R to U is R–S–T–U, with weight \(9\).
